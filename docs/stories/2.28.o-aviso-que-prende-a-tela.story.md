## 🔍 AC0 — parte RODADA antes de escrever (2026-08-12)

> O AC0 desta story começou por **derrubar** a hipótese que eu mesmo registrei ontem como principal.

### 1. 🛑 O `FocusTrap` **não é** novidade da 2.27 — está lá desde o primeiro commit

```
git log --oneline -S"<FocusTrap active={isOpen}" -- features/boards/components/Modals/DealDetailModal.tsx
→ f50fc64  chore: initial commit
```

⇒ **Se o trap fosse causa suficiente, o defeito seria anterior a tudo** — e a 2.27 não teria como ser a regressão. O que a 2.27 fez foi **estrear um caminho** (um diálogo em portal que aparece no fechamento), não criar o mecanismo.

### 2. 🔍 Os dois diálogos em portal são **estruturalmente idênticos**

| | `FecharComPendenciasDialog` (2.27) | `ConfirmDialog` — excluir card |
|---|---|---|
| Primitivo | Radix `AlertDialog` | Radix `AlertDialog` |
| Renderização | `AlertDialogContent` → **`AlertDialogPortal`** (`alert-dialog.tsx:34`) | **a mesma** |
| Onde é montado | dentro de `inner`, **sob o trap** (`DealDetailModal.tsx:1413`) | dentro de `inner`, **sob o trap** (`:1347`) |

🎯 **A previsão fica binária e testável: ou os DOIS estão mortos, ou nenhum.** Não existe terceira hipótese em que só o novo quebre — eles são o mesmo componente com props diferentes.

### 3. ✅ Os outros overlays do modal **não** usam portal — e isso estreita o escopo

| Overlay | Portal? | Prognóstico |
|---|---|---|
| `FecharComPendenciasDialog` | 🔴 **sim** (Radix) | suspeito |
| `ConfirmModal` (excluir card) | 🔴 **sim** (Radix) | suspeito |
| `LossReasonModal` | ✅ não — `<div role="dialog">` inline | fora do raio |
| `BriefingDrawer` | ✅ não — `<div role="dialog">` inline | fora do raio |

⇒ **A classe tem exatamente 2 membros**, não "todos os diálogos". Consertar a causa cobre os dois; os outros dois nunca estiveram em risco porque vivem **dentro** do container do trap.

### 4. 🕳️ Por que os 602 testes passaram — e não é "teste não tem ponteiro"

```tsx
// features/boards/components/Modals/DealDetailModal.test.tsx:132
FocusTrap: ({ children }: { children: React.ReactNode }) => <>{children}</>,
```

**O suite arranca o trap antes de testar.** O componente sob teste nunca foi o componente que roda em produção.

🔑 **A consequência é boa:** o defeito é reproduzível **em teste, sem navegador e sem `.env.local`** — basta montar com o `FocusTrap` real. Isso derruba a parede que bloqueou o `AC6` da 2.27 e o `AC0.3` da 2.23.

### 5. 🧩 O mecanismo, lido no código

```tsx
// lib/a11y/components/FocusTrap.tsx:42,68
clickOutsideDeactivates = false,          // default
allowOutsideClick: clickOutsideDeactivates,   // ⇒ false
```

`focus-trap` com `allowOutsideClick: false` **cancela o clique de fora do container** e devolve o foco para dentro. O container é `<div data-focus-trap-fallback>` (`:76`); o conteúdo do Radix está no `document.body`, **fora** dele. ⇒ os cliques nos 3 botões são "de fora".

Versões: `focus-trap-react ^11.0.6` · `@radix-ui/react-alert-dialog ^1.1.15`.

## 🔧 O conserto — duas camadas

### A. `lib/a11y/components/FocusTrap.tsx` — a causa, genérica

```diff
- allowOutsideClick: clickOutsideDeactivates,   // ⇒ false, e mata todo portal
+ allowOutsideClick,                            // prop própria, default true
```

As duas opções diziam coisas diferentes e estavam amarradas na mesma. Agora: `clickOutsideDeactivates: false` segue dizendo *"clicar fora não me desliga"*; `allowOutsideClick: true` diz *"mas eu não cancelo o clique de ninguém"*. **Confinamento de `Tab` — o motivo de o trap existir — não muda** (AC5).

⚠️ **Compatibilidade conferida:** o único call site que passa `clickOutsideDeactivates={true}` (`OnboardingModal.tsx:40`) já tinha `allowOutsideClick: true` pelo acoplamento antigo ⇒ **comportamento idêntico**, sem regressão.

### B. `DealDetailModal.tsx:1449` — a briga de foco entre dois traps

```diff
- <FocusTrap active={isOpen} onEscape={tentarFechar}>
+ <FocusTrap active={isOpen && !avisoPendencia && !deleteId} onEscape={tentarFechar}>
```

O conserto A libera o **clique**; sozinho, ele deixaria o **teclado** quebrado — o Radix traz o próprio confinamento, e dois traps ativos disputam o `focusin`, com o de fora puxando o foco de volta ao card. **Ceder não afrouxa acessibilidade: transfere-a para a camada de cima**, que é quem deve mandar.
