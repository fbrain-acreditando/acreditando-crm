|---|---:|

🎯 **6 de 11 são distância — e os 5 botões prontos, somados, foram usados 2 vezes.**
⇒ **O motivo mais comum dela é o único que não tem botão.** É por isso que ela digita à mão, e é por isso que a grafia divergiu em **3 variantes do mesmo motivo**. Agrupar por motivo hoje é impossível.

📖 Casa com o que o vault já registrava sobre ela: *"a objeção nº 1 que ela enfrenta é **logística**, não preço — *'não tem quem me leve'* — é daí que nasce a fila de leads mornos"*.

⚠️ **Consequência para 14/08:** se ela mostrar "motivos de perda" na apresentação, **distância aparece como 3 linhas distintas** e o motivo campeão parece minoritário. → **AC5**.

### Pedido 2 — a causa, lida no código (não suposta)

`features/boards/components/Modals/DealDetailModal.tsx:854` e `:868`

```tsx
<input
  value={deal.customFields?.[field.key] || ''}   // ← valor vem SÓ do servidor
  onChange={e => updateCustomField(field.key, e.target.value)}  // ← grava a CADA tecla
/>
```

O input é **controlado pelo dado do servidor**, sem estado local. E `updateCustomField` (`:409`) dispara `updateDeal` **a cada tecla**.

**Por que pisca — a sequência exata:**

| # | O que acontece |
|---|---|
| 1 | Ela digita `D` → `onMutate` faz update otimista → o `D` **aparece** |
| 2 | Ela digita `i` → 2ª mutation → otimista `Di` |
| 3 | A 1ª mutation resolve → `onSettled` faz `invalidateQueries(deals.all)` (`useDealsQuery.ts:394`) |
| 4 | O refetch **aterrissa com o valor `D`** do servidor → o input **volta para `D`** ← *"apaga sozinho"* |
| 5 | A 2ª mutation resolve → refetch → `Di` **reaparece** ← *"depois aparece"* |
| 6 | Repete a cada tecla ⇒ **pisca** |

O `cancelQueries` do `onMutate` cancela o que está **em voo naquele instante**; um refetch disparado **depois** ainda aterrissa com dado velho. O otimismo existe e **não** resolve: o problema é a **reconciliação chegando atrasada** sobre um input sem memória própria.

🔴 **E o custo escondido — determinístico, não estimado:** o `dealsViewQueryFn` faz **4 consultas** (deals + stages + contacts + companies). `invalidateQueries(deals.all)` por tecla ⇒ digitar **"Distância" (9 letras) = 9 UPDATEs + 9 broadcasts de Realtime + ~36 consultas**. É a lentidão da story 2.23 **sendo produzida ao vivo pela digitação dela**.

⇒ Os 5 campos personalizados (`tipoDeLesao`, `ondeReside`, `haQuantoTempo`, `jaFezReabilitacao`, `paraQuemE`) são **todos `type: text`** ⇒ **todos passam por este input.** Nenhum é `select`.

### ✅ A convenção certa já existe neste repo

`components/LeadNameEditor.tsx` (story 2.20) resolve exatamente isto:

```tsx
const [valor, setValor] = useState(displayName);
useEffect(() => { if (!editando) setValor(displayName); }, [displayName, editando]);
```

**Estado local, que só acompanha o servidor quando o campo NÃO está sendo editado.** É o padrão da casa — a story segue ele em vez de inventar debounce.

## Critérios de aceite

### AC1 — O campo personalizado para de piscar
- [ ] Input passa a ter **estado local**; o valor do servidor só sobrescreve quando o campo **não está com foco**
- [ ] Gravação **ao sair do campo** (`onBlur`) e no **Enter** — não a cada tecla
- [ ] `Escape` descarta a edição e volta ao valor do servidor
- [ ] `select` (hoje inexistente, mas suportado) continua gravando **na hora** — ali não há digitação, então não há corrida

## ✅ Execução — 2026-08-11

### AC1 + AC2 — o campo para de piscar (✅)

Componente novo `CustomFieldInput.tsx`, seguindo a convenção do `LeadNameEditor` (story 2.20): **estado local**, e o servidor só sobrescreve quando o campo **não está sendo editado**. Grava no `onBlur` e no `Enter`; `Escape` descarta.

**Digitar "Distância" saiu de 9 UPDATEs → 1.** E sair do campo sem alterar nada agora grava **zero**.

🪤 **Dois defeitos MEUS, pegos pelos testes e não por revisão:**
1. **`Enter` gravava duas vezes** — ele chamava `salvarSeMudou()` e depois `.blur()`, que redisparava o `onBlur`.
2. **`Escape` gravava assim mesmo** — `setValor` é assíncrono, então o `onBlur` seguinte lia o `valor` **velho** e o persistia. O usuário apertaria Escape para descartar e o descarte gravaria.

⇒ `editandoRef` passou a significar **"já tratei"**, não só "está editando", e o `salvarSeMudou` sai cedo se já foi tratado. *Escrevi o conserto e o conserto tinha dois bugs; quem achou foi o teste.*

### AC3 — "Distância" nos motivos de perda (✅)
Primeiro da lista, ícone `MapPin`, `value` canônico **`'Distância'`**. Comentário no código explica que **mudar um `value` fragmenta o histórico** — para renomear, migrar as linhas junto.

### AC4 — os testes discriminam (✅)
