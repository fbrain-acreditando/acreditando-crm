## 🔍 AC0 — RODADO antes de escrever

### O suspeito, e o precedente que já estava escrito no repo

```js
// useUpdateDeal.onSettled (antes)
queryClient.invalidateQueries({ queryKey: queryKeys.deals.all });
```

Esse `invalidate` **refetcha na hora**. O refetch parte logo depois da escrita e pode aterrissar com **leitura stale** por cima do update otimista.

📌 **Não é teoria minha: o repo já tinha diagnosticado e resolvido isso — no hook irmão.**

```js
// useMoveDeal.ts:336-343
// NOTE: We DON'T invalidate here to avoid race condition with Realtime.
// 3. onSettled invalidates → refetch (may get stale data if timing is off)
// 4. Realtime UPDATE arrives → invalidates again → refetch (may overwrite with old data)
```

O caminho de **mover card** removeu o invalidate por esse motivo exato. O caminho de **editar campo** manteve. ⇒ o defeito não era desconhecido; era **desigual**.

### A reprodução — e ela devolveu o sintoma com as palavras dele

Teste com `QueryClient` real, observer ativo e um servidor que devolve **de propósito** a leitura antiga (o caso que a corrida produz). Com o código antigo:

```
AssertionError: expected 'Santos' to be 'Guarulhos'
```

**`'Santos'` é o valor velho.** O cache voltou atrás sozinho — exatamente *"aparece rapidamente o antigo"*. Com o conserto, o teste passa.

---

## 🔧 O conserto — uma linha, e a rede de segurança fica

```diff
- queryClient.invalidateQueries({ queryKey: queryKeys.deals.all });
+ queryClient.invalidateQueries({ queryKey: queryKeys.deals.all, refetchType: 'none' });
```

⚖️ **Por que não simplesmente apagar a linha** (que é o que o `useMoveDeal` fez): o `invalidate` também servia de **rede de segurança** — reconciliar com o banco caso o Realtime não dispare. `refetchType: 'none'` **preserva a rede e remove só a corrida**: a query é marcada como *stale*, e o `refetchOnMount` do `useDealsByBoard` — que já testa `query.state.isInvalidated` — reconcilia na próxima montagem.

🎁 **De quebra, some um refetch do board inteiro a cada campo salvo.** O `dealsViewQueryFn` faz **4 consultas** — era o custo que a story 2.26 mediu e reduziu de 9 escritas para 1; agora cai também o refetch que sobrava de cada uma.

## Fora de escopo (declarado, com o motivo)

- ❌ **`useCreateDeal` e `useDeleteDeal` seguem refetchando.** É **intencional**: um card recém-criado precisa do enriquecimento que só o `dealsViewQueryFn` monta (`contactName`, `companyName`, `stageLabel`). Ali o refetch **traz** informação, em vez de competir com o otimismo.
- ❌ **`useUpdateDealStatus`** — está marcado `@deprecated` e sem call site; mexer só ampliaria o raio.
