## O que já existe (lido na `origin/main` = `1953e33`)

- **Tela (`lib/query/hooks/useMoveDeal.ts:124-129`):** arrastar um card fechado para uma coluna comum **reabre**: `isWon = false`, `isLost = false`, `closedAt = null`. A exceção são as colunas de categoria (`board_stages.arquiva_sem_reabrir = true`, story 2.40), que arquivam sem reabrir.
- **API pública (`lib/public-api/dealsMoveStage.ts`, `moveStageByDealId`):** só mexe em `is_won`/`is_lost` quando o destino é a etapa de Ganho/Perdido ou `mark` = `won`/`lost`. Mover um card perdido para uma coluna comum **mantém `is_lost = true`**. A API diverge da tela.
- **`PATCH /deals/{id}`** não aceita `is_lost` (schema `.strict()`). **Não existe rota pública que reabra.**
- **Quem chama:** o subfluxo n8n `jph8ikeE49UQRntu` ("Remarketing nov → coluna da campanha") faz `POST /deals/{id}/move-stage {to_stage_id: d0171b1d-…}`.
- **Coluna "Campanha Novembro":** `d0171b1d-3043-420f-8459-7db8aae35947`, `arquiva_sem_reabrir = false`.
- **Gatilhos em `deals` (produção, lidos em 05/11):** `check_deal_duplicate_trigger` (BEFORE INSERT/UPDATE), `trg_enfileirar_pontuacao_*` (só `stage_id`), `trg_notify_deal_stage_changed`. Nenhum reage a `is_lost`.

## Decisão de arquitetura

**Opt-in, não mudança geral.** Novo valor `mark: "reopen"` no `POST /deals/{dealId}/move-stage`. Sem `mark`, a rota se comporta **exatamente** como hoje.

Motivo: outros chamadores da API (fluxos n8n, integrações) podem depender do comportamento atual. Mudar o padrão para todos é decisão maior; o caso de hoje é um só chamador conhecido.

Regra de `mark: "reopen"` (espelha a tela):
- Destino é etapa comum (não é a de Ganho, não é a de Perdido) **e** `arquiva_sem_reabrir = false` → `is_won = false`, `is_lost = false`, `closed_at = null`.
- `loss_reason` e `loss_note` **ficam** (são histórico de por que foi perdido; a tela também não apaga).
- Destino é Ganho, Perdido ou coluna com `arquiva_sem_reabrir = true` → **422** `VALIDATION_ERROR` ("reopen não vale para esta etapa"), nada é gravado.
- Card já aberto + `reopen` → só move (idempotente).

`move-stage-by-identity` fica fora: ele só encontra cards abertos.

## Critérios de aceite

1. **AC1** — `POST /deals/{id}/move-stage {to_stage_id: <comum>, mark: "reopen"}` num card com `is_lost = true` devolve 200 com `is_lost: false`, `is_won: false`, `closed_at: null`, `stage_id` = destino.
2. **AC2** — o mesmo com `is_won = true` também reabre (mesma regra da tela).
3. **AC3** — `loss_reason` (e `loss_note`) continuam com o valor de antes.
4. **AC4** — `mark: "reopen"` com destino Ganho, Perdido ou coluna `arquiva_sem_reabrir = true` → 422, e o card **não** muda (nem etapa).
5. **AC5** — sem `mark`, e com `mark: "won"`/`"lost"`, o comportamento é idêntico ao de hoje (testes de regressão).
6. **AC6** — OpenAPI (`lib/public-api/openapi.ts`) documenta `reopen` no `/deals/{dealId}/move-stage`.
7. **AC7** — em produção, depois do deploy: o subfluxo n8n passa a mandar `mark: "reopen"`; read-back num card real que veio de Perdido mostra `is_lost = false` na coluna "Campanha Novembro". Se nenhum lead perdido transferir até lá, read-back com chamada da API num card de teste criado e apagado com autorização.
8. **AC8** — `npm run typecheck`, `npm run lint` e os testes da área passam.
